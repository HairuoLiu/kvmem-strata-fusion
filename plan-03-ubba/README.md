# 方案三 UBBA —— 统一字节预算器（Universal Byte-Budget Allocator）

> **一句话定位**：纯控制面，按 `min bytes s.t. ρ ≤ ρ_floor ∧ coverage ≥ target` 分配 KV 字节；无 kernel、无训练、失败模式是"不够好"而非"崩掉"。

## 立项依据（被 5 个 agent 独立撞见却没人申报的结构性事实）

所有方案都在隐式解决"字节预算怎么分"，但没人把它做成一等公民。IFR 在保真门前偷偷分配字节，LADDER 在水位线下分配档位，CASA 在 canonicalize 时分配——都是同一份决策的不同切面。UBBA 把它抽出来，做成一个可被其它方案调用的求解器。

## 关键设计

- **形式化初版**：原目标函数 `max coverage s.t. bytes` 被 R3/R4/R6/R5/R10 五人独立否决——无保真项 ⇒ 背包必填满最便宜档 ⇒ −12.7pp。修正为约束集 `min bytes s.t. ρ ≤ ρ_floor ∧ coverage ≥ target`，保真作为硬约束而非优化目标。
- **差异化**：与 IFR/LADDER/CASA 真正正交——它是控制面而非系统；天然吸收其它方案的成果（字节模型一旦标得准，就是 CASA 字节线的求解器）。
- **最短出成果路径**：P0–P1（14 人日，基本离线）即可出模型与离线回放结论。
