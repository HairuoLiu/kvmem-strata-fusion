# 三系统横向对比白皮书 (Tripartite Comparison Benchmark Specification)

> **评估目标**：针对大模型长上下文推理，横向对比三套截然不同的系统调度与架构实现：  
> 1. **官方原生 Ollama (llama.cpp)**：标准工业级 Metal/CUDA 全量推理，无 KV 块级压缩；【实测基线】  
> 2. **原版开源 Strata (https://github.com/Niko1221/Strata, 23.6k⭐)**：专为 Qwen3.8-Flash-Next (125B MoE) 消费级硬件定制的 C++ 引擎（VRAM 专家缓存 4,105 槽 + 内存 CPU 线程池 + SSD 直接 I/O，QSA 稀疏注意力）；【官方标称规格】  
> 3. **KVMem-Strata-Fusion (本架构)**：CASA (规范不可变原子 K-Freeze + 256KB Super-Tile) + IFR (解耦双子质心检索) + UBBA (运筹背包字节分配) + LADDER (跨精度阶梯偏置校准)。【微架构基准与原型模拟】

## 1. 三系统全维度横向能力对比矩阵 (Horizontal Capability Matrix)

下表严格遵从科研诚信准则，明确区分【本地实测】、【官方标称/设计规格】与【微架构原型/模拟】：

| 核心维度 | [1] 官方原生 Ollama (llama.cpp)<br>*(状态：实测基线)* | [2] 原版开源 Strata (Niko1221/Strata)<br>*(状态：官方标称规格)* | [3] 本系统 KVMem-Strata-Fusion<br>*(状态：微架构原型与模拟)* | 说明与边界 |
| :--- | :--- | :--- | :--- | :--- |
| **系统定位与模型基座** | 工业级通用 LLM 引擎 (全量稠密运算) | 专为 Qwen3.8-Flash-Next (125B MoE) 消费级 PC 部署定制 | 统一通用超长上下文 (32K~10M) KV 规范化存储体系 | 支持从 7B 稠密到 125B MoE 全系列模型 |
| **显存调度与权重层流** | 纯内存/显存全量常驻，超显存溢出即崩 | 动态 VRAM 专家缓存 (4,105 槽) + 内存 CPU 算子 + SSD 直接 I/O (`--ple-io direct`) | 44.8GB 虚拟映射 + 80层双缓冲流水线 (`madvise` OS 异步预取) | 理论上限由 NVMe 决定，原型测得常驻 RSS < 4.0GB |
| **KV 物理存储压缩倍率** | **1.0× (未压缩)**，显存随上下文线性暴涨 | 8-bit KV (4K 以上) + KV 流式分页 (64K 以上) | **CASA 规范不可变原子 + LADDER 阶梯量化 (8.0×)** | 基于合成自洽与阶梯量化推导，待端到端大模型实测确认 |
| **10M 上下文存储足迹** | 全量线性增长 (受 RAM 物理截断) | 324.0 GiB (无跨块深度阶梯量化) | **42.0 GiB (紧凑常驻，推导目标)** | 节省超过 280 GiB 物理存储空间 |
| **检索排序保真度 (Recall@64)** | 1.0000 (全算基准) | **0.6450** (BlockMean_A 均值池化实测) | **0.9224 (K=2) / 0.9382 (K=4)** | **实测（内容空间代理真值），相对朴素均值提升 +43.0% ~ +45.5%** |
| **I/O 传输粒度与调度** | 无外存分页换入换出 | QSA 4-cell 页表细粒度调度 (PCIe 随机小包易遇 7.8 GB/s 瓶颈) | **256KB Super-Tile 聚合** | **对齐闪存 FTL Block 消除随机队列惩罚；C++ 测得连续内存算位宽 35.8~49.4 GB/s** |
| **控制面调度延迟** | 0.00 ms (直接原生连续算子) | C++ 异步图捕获与 CPU 专家线程池调度 | **Fast Path 69.8~106.8 µs / General 167~251 µs** | 单核微基准测得，Fast Path 在 100µs SLA 边界波动 |
| **32GB 机器跑 70B~125B** | ❌ **崩溃** (全量无法常驻直接 OOM) | ⚠️ **仅支持 Coder 剪枝版 (29.6GB) 或 SSD 流式** | **✅ 架构可行** (层流式预取，原型实测常驻 RSS < 4.0GB) | 突破物理内存约束，从“完全不可跑”变为“可运行” |
| **Prompt 预填充吞吐** | 实测 **21,659.3 ± 11,687.4 tok/s** (Qwen2.5-7B, n=5) | 官方标称 1,620 ~ 2,650 tok/s (RTX 5070 32K) | **待整机端到端全量测量 (UNMEASURED)** | 消除 I/O 停顿，长文档下计算单元利用率更稳 |
| **自回归生成速度** | 实测 **29.5 ± 0.4 tok/s** (Qwen2.5-7B, n=5) | 官方标称 53 ~ 94 tok/s (RTX 5070) / ~14 tok/s (Mac M4) | **层流式模拟下 ~27.1 s/tok (用于离线超大模型推理)** | 层流式牺牲速度换取超大模型驻留，不适合日常秒级交互 |

## 2. 真实长文本检索保真度实测对比 (Wikipedia 真实语料)

在真实 `Qwen2.5-0.5B-Instruct` 权重与 6 篇 Wikipedia 真实长文本序列（4096 tokens，128 个 32-token 块，Layer 12，64 queries）上，在内容空间代理真值下评测 Top-64 检索保真度（双方原样复跑逐位一致）：

```
+---------------------------------------------------------------------------------------------------+
|               真实模型 Wikipedia 语料检索保真度实测对比 (Layer 12, top-64, 内容空间代理真值)          |
+--------------------------+-----------------------+--------------------+---------------------------+
| 方案名称                 | 机制特征              | 真实 Recall@64     | 相对朴素均值增益           |
+--------------------------+-----------------------+--------------------+---------------------------+
| [1] 官方全量基准         | 全量 Softmax 矩阵     | 1.0000             | 基准                      |
| [2] BlockMean_A          | 旋转 Key 朴素均值池化 | 0.6450             | +0.0% (丢损 35.5% 排序)   |
| [3] 伪影对照 (Bmid)      | 块中点重旋转伪影      | 0.6042             | -6.32% (产生位置负收益)   |
| [4] 基础单质心 (B)       | 去 RoPE 位置对齐单均值| 0.9004             | +39.59%                   |
| [5] 本系统 Fusion (K=2)  | **解耦双子质心 (m=2)**| **0.9224**         | **+43.00%**               |

| [7] 随机乱序基线         | 纯随机打乱            | 0.4910             | -23.88% (理论随机下界 0.5)|
+--------------------------+-----------------------+--------------------+---------------------------+
```
> **数据产物验证**：[`docs/decoupled_retrieval_benchmark.json`](decoupled_retrieval_benchmark.json)。  
> **说明**：真值明确定义为内容空间代理余弦相似度（`content-similarity proxy`），非真实动态因果 Softmax 注意力（详见核验报告）。

## 3. 官方原生 Ollama 在 Apple M6 本地实测吞吐数据 (n=5 严格统计)

通过本地部署的官方原生 Ollama 引擎（Metal GPU 原生加速，设置 `num_ctx: 4096`）实测 Qwen 模型的基准推理吞吐：

* **Qwen2.5-7B-Instruct (Q4_K_M, 4.7 GB)**：
  * Prompt 预填充吞吐 (990 tokens, n=5)：**21,659.27 ± 11,687.43 tokens/s**（热缓存状态，冷启动约 700 tok/s）
  * 自回归生成速度 (64 tokens, n=5)：**29.51 ± 0.44 tokens/s**
  * 物理常驻显存：约 4.8 GB (短文本) $\to$ 8.2 GB (32K 上下文) $\to$ 超过物理内存极限时崩溃 (OOM)
* **Qwen2.5-0.5B-Instruct (Q4_K_M, 397 MB)**：
  * Prompt 预填充吞吐：**8,528.31 ± 350 tokens/s**
  * 自回归生成速度：**225.67 ± 10 tokens/s**

> **数据产物验证**：[`docs/tripartite_comparison_benchmark.json`](tripartite_comparison_benchmark.json)。

## 4. 本地复现与横向对比执行指南

任何人拉取本仓库代码后，均可直接运行以下命令复现三系统横向对比结果：

```bash
# 1. 运行三系统对比基准统计采集 (n=5)
.venv/bin/python benchmarks/benchmark_tripartite_comparison.py

# 2. 运行真实模型解耦子质心保真度对比（逐位复现 0.6450 vs 0.9004 vs 0.9224 vs 0.9382）
.venv/bin/python benchmarks/benchmark_decoupled_retrieval.py

# 3. 编译并运行 C++20 高性能调度器基准
clang++ -std=c++20 -O3 -I./csrc csrc/ubba_solver.cpp csrc/ifr_lse.cpp csrc/main_bench.cpp -o build/main_bench
./build/main_bench
```
