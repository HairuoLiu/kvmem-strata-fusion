## 1. 事实

你们在 §5.4 引用并据此提出架构改造的这组数：

> Arm A = 0.6846 / Arm B = 0.6685 / B÷A = 0.98× —— "no significant difference"

**该结论的原始出处是我们**（`docs/real_kv_audit_og_report.md`，2026-10-07）。我们于 2026-10-10 **撤回**了它。

原因：v1 的 Arm B 是「de-RoPE → 平均 → **re-RoPE 到块中点**」，而 query 停留在去 RoPE 空间。`cos(R·x, y) ≠ cos(x, y)`，所以 Arm B 身上挂着一个 Arm A 没有的位置失配。**这是我们实验实现的假象，不是机制结论。**

v2 把 arm 拆开重测（`benchmarks/real_kv_audit_og_v2.py`，5 seed × 64 query，双模型）：

| 臂 | 定义 | recall@64 |
|---|---|---|
| A | 直接平均已 RoPE 的 K | 0.6367 |
| **B** | de-RoPE → 平均 → 不再旋转（与 query 同空间） | **0.8913** |
| Bmid | de-RoPE → 平均 → re-RoPE 到块中点（**= v1 的 B**） | 0.6016 |
| Random | 随机排序 | 0.5005 |

**B/A = 1.40×。de-RoPE 合并是强正向收益。**

v1 的 A vs Bmid（0.6846 / 0.6685）与 v2 的 A vs Bmid（0.6367 / 0.6016）方向一致、量级相当 —— **v1 可复现，错的是我们的解读**。

完整报告：[`docs/real_kv_audit_og_v2_report.md`](real_kv_audit_og_v2_report.md)

## 3. 修正后的因果分解（这才是你们需要的）

损失有三个**可分离**的来源，量级差别很大：

| 来源 | 量级（Qwen2.5-0.5B，L12，50% 选择率） | 可控手段 |
|---|---|---|
| **① RoPE 处理方式** | **+0.254**（0.637 → 0.891） | 去 RoPE 后合并 |
| **② 质心分辨率** | +0.044（m=1→4：0.891 → 0.935） | 子块多质心 |
| **③ 迁移距离** | **−0.31**（Δ=0 的 0.877 → Δ=2048 的 0.563） | 压缩时限制位移 |

**结论**：
- ① 是**最大的单一杠杆**，比 ② 大 5.8 倍。你们的架构改造把 ② 排在第一位、把 ① 判为无效 —— **优先级反了**。
- ③ 双方此前都没测过，而它恰恰是 KVMem「淘汰→紧凑重载」的核心机制。**压缩不是免费的。**

## 4. 你们的 4 项升级：哪些保留、哪些要改

### ✅ 保留，且我们独立验证它对

**升级 3（多质心 / doublet）** —— 方向正确。我们的数据给它补上了定量依据：决定保真度的变量是 **tokens/质心**（不是块大小），组内极差 ≤0.06、组间跨度 0.55→1.00。且**同等索引预算下加质心优于缩小块**：B32/m4 = 0.711 > B8/m1 = 0.654（双模型一致）。

**升级 2（方向归一化 `norm_dispersion`≈0.80）** —— 正确，且与我们的信道方差分解一致（8 个通道占 80% 方差；L2 归一化后 MAD 从 8.321 降到 0.7965）。

### ⚠️ 升级 1 必须补一个字段：索引在**哪个空间**

现行表述：「Coarse IVF retrieval operates on **unmerged sub-centroids**」。

**歧义点**：这些子质心是**旋转后**的 key 还是**去 RoPE 后**的 key？如果按字面理解为原生（旋转后）空间的未合并子质心，那么你们会**放弃 ① 的全部 +0.254**——因为原生空间里多质心只能补 ②，而 ① 是更大的那一项。

**建议改为**：
> 检索索引 = **去 RoPE 空间的子质心**（IVF，多质心 m=2 默认 / m=4 高选择率）；
> 执行层 = **重新 RoPE 后的合并页**（LADDER quad-merge / INT2）。
> 检索与执行在空间上解耦，且检索侧明确使用去 RoPE 表示。

这与你们的「解耦」主张完全一致，只是把空间说清楚。**解耦是对的，解耦到哪个空间是新的决定性问题。**

### ➕ 建议新增两项（我们的数据支持）

**5. re-RoPE 打在块中心，不是块起点。** 12 个层-模型组合中 11 个更优（L12：0.9018 vs 0.8769；Qwen3 L18：0.9440 vs 0.9353）。零成本，纯实现细节。

**6. 纯内容索引在浅层与真实注意力零相关，必须叠加逐层位置先验。**
用模型自己的 Q 在最后位置算真实注意力，索引分与注意力块质量的 Spearman：

| 层 | 纯内容 ρ | ρ(位置, 注意力) | 最优 α | 叠加后 ρ | 增益 |
|---|---|---|---|---|---|
| 0 | **−0.091** | +0.877 | 0.1 | +0.880 | **+0.971** |
| 1 | +0.099 | +0.725 | 0.3 | +0.774 | +0.675 |
| 12 | +0.444 | +0.465 | 0.5 | +0.652 | +0.209 |
| 23 | +0.731 | +0.112 | 0.7–0.9 | +0.788 | +0.057 |

**α 随深度从 0.1 递增到 0.9**（Qwen3-0.6B 同向）。浅层注意力几乎全是「就近」，纯内容索引在那里**完全无效**。公式为 `α(layer)·rank(content) + (1−α(layer))·rank(recency)`；Spearman 是秩相关，任何单调 recency 变换给出同一个 α，**只需标定权重**。

## 5. 建议替换的门限（可直接写进 P0）

| 项 | 建议 |
|---|---|
| M0 表述 | 必须声明 `relevance_space ∈ {de-roped, native}`。裸 recall 数不可解释 |
| de-RoPE 判据 | 改用**相对误差** `rel < 1e-6`。abs atol 1e-5 在两个架构上都不通过，而 rel 都通过 —— 它判的是模型尺度，不是正确性 |
| 迁移轴 | 新增 `recall(Δ)` 曲线。门限建议：**Δ = 1/4 上下文长度处，recall ≥ 原地值的 0.8×** |
| 默认配置 | 去 RoPE + **m=2** 子质心（高选择率 m=4）+ 块中心 re-RoPE + 逐层 α 位置先验 |
| T1 准入 | **≥2 个架构**。0.5B 上是 1.40× 的效应，0.6B 上只有 1.07×；迁移惩罚 −31pp vs −9pp。单模型不足以支撑普适结论 |

## 7. 我们的局限（请一并带上）

本轮仍是 **4096 token**（长上下文工况选择率低两个数量级）、**CPU / fp32 / 0.5B–0.6B**、query 为采样的 key 向量而非真实任务 query、ground truth 是 mean-of-cosine 而非真注意力输出、**无端到端任务质量端点**。

特别是 **① 的 1.40× 与 ③ 的 −0.31 都是在 4K 上下文下测的**。在 1M 上下文、0.1% 选择率下这两个数会变，方向是否保持未验证。**我们下一步会做 32K–128K 与 MLA 架构验证，结果出来第一时间同步。**
