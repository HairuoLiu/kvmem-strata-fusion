### 逐层结果（n=256 块·头/层）

| 层 | Arm A | Arm B | B/A |
|---|---|---|---|
| L0 | 0.3346 | 0.9987 | 2.98× |

1. **三个数值互不相等**，差异来源是**语料**：合成 0.16 → 重复段落 0.44 → 异质语料 0.50。

2. **真实值 0.4979 而非理论 0.1768**：我们已撤回的 82% 论证（见 v3 §10）方向正确，但真实值比我们的上界还高。
3. **B/A = 1.86×**，与外部团队报的 2.14× 同量级。

## 3. 【决定性结果】recall@64：de-RoPE 合并**没有**改善检索排序

这是 v2 要求的缺失判据，也是本组认为**最有价值的一项测量**。

### 定义（明确写出以便复核）

```
query       = 某块的**真实** de-RoPE 均值（无位置污染、未压缩）
groundTruth = 按 cos(query, 真实块均值) 排序  → top-64      ← 等价于"穷举 Mean-K"
armA        = 按 cos(query, Arm A 合并向量) 排序 → top-64     ← 直接平均已 RoPE
armB        = 按 cos(query, Arm B 合并向量) 排序 → top-64     ← de-RoPE→平均→re-RoPE
recall@64   = |top-64(arm) ∩ top-64(truth)| / 64
```
64 个随机查询块，取自 Layer 12。

### 结果

| 臂 | recall@64 |
|---|---|
| Arm A（不 de-RoPE） | **0.6846** |
| Arm B（de-RoPE 合并） | **0.6685** |
| **B/A** | **0.98×** |

### 这个结果为什么重要

**Arm B 并不比 Arm A 好。** 两者都只保留了约 **67%** 的 top-64 集合，相对穷举真值**各损失约 1/3**。

这意味着：

1. **M0 判据"B 的掉点 ≤ A 的 1/3"是空洞通过的。** 它之所以 PASS，是因为 A 和 B **都很差**（0.68 / 0.67），而不是因为 B 好。这个判据在当前设计下**没有区分力**。
2. **我们 LADDER L2′ 的技术前提未获支持。** "必须先 de-RoPE 再合并才能保住检索"——真实数据不支持。真正的损失来源不是 RoPE 处理方式，而是**块均值合并本身**。
3. **外部团队的两条结论都需要降级**：
   - "M0 PASSED"：在一个无区分力的判据上通过；
   - §4.1 的"压缩侧保真 99.8%"：那是 `cos(IFR, Oracle)`，与本节的 `recall@64` 是**两个不同的量**。前者好不代表后者好——而后者才是检索真正依赖的。

### 更一般的结论（我认为这比上面任何一条都重要）

> **块均值合并对检索排序的损伤，与 RoPE 处理无关。** 要提升检索保真，改进方向不是"更小心地处理位置"，而是：
> - 保留块内子结构（如 §3.2 的位置残差 / rank-r 残差），或
> - 降低合并粒度（G=4 → 更大 G 的块内多质心 / 分层质心），或
> - 把合并从"检索路径"移到"执行路径"（检索用未合并的粗排向量，执行时才合并）。

**这一条直接给出 LADDER 的改进方向，而不是只否定它。**

### ⚠️ 本实验的局限（必须声明）

- **Arm B 的重旋转位置**：我把 Arm B 旋转到块中点，而 query 是 de-RoPE 的，残留位置失配。这对 B **略不利**。一个把 Arm B 旋转到与 query 同一位置的变体可能让 B 略好。但鉴于 A、B 差距仅 2%，结论"B ≈ A"对这一设定**不敏感**。
- n=64 查询、单一 0.5B 模型、单一 seed；T=4096。
- 这是**索引空间自检索一致性**，不是端到端任务效用。端到端需 T2（256K + 真实 benchmark）。
- **不要**把它读成"合并不可行"。它是"**在当前合并方式下**，检索排序损失约 1/3"。

## 4. σ=8.03 是**幅度伪影**，不是语义分散度

外部团队实测 σ_K=8.03，并据此判定"合成假设 σ=0.02 是人为的"。本组独立得到 **σ_K=8.321**（逐层 min 4.570 / max 12.717）——**与其高度一致，交叉验证通过**。

但我们进一步做了**逐通道分解**，结论改变：

| 度量 | 值 |
|---|---|
| 未归一化 key 的块内 MAD | **8.321** |
| **top-8 通道占总方差** | **34.8%** |
| **仅 8 个通道（64 维的 12.5%）占总方差** | **80%** |
| 剔除 top-8 通道后的 MAD | 11.375 |
| **L2 归一化 key 后的 MAD** | **0.7965** |

### 结论

把 key 归一化后，块内离散度从 **8.32掉到 0.80**（**10.4 倍**）。这说明：

> **σ ≈ 8.03 几乎完全由少数 massive-activation 通道的幅度决定，而不是 token 之间的语义分散。**

### 对外部方案的直接后果

动态阈值 `θ = μ_block + k·σ_block` 在真实数据上的问题是：

- **阈值由异常幅度通道决定，与"是否含语义针尖"无关**；
- 后果一：**一个语义无关但幅度大的 token 会被判为"针尖"**（假警，来自幅度）；
- 后果二：**一个真正相关但幅度正常的针尖会被漏掉**（漏检，来自幅度门限）；
- 后果三：若为消除这一影响而做 L2 归一化，则阈值须在**方向空间**重新标定——此时 σ=0.80，与他们扫描的 σ∈[0.02,0.30] 差 2.7 倍，仍在扫描区间之外。

**所以 v3 §4 指出的"真实工作点未被覆盖"，在归一化后依然成立**，只是真实工作点从 8.03 变成 0.80。

## 5. 交给外部团队的四个可执行改进

基于以上，这是我们能给出的**具体建设性方案**，而不只是问题清单：

| # | 改进 | 依据 | 成本 |
|---|---|---|---|
| 1 | **把 LADDER L2′ 从"检索路径"移到"执行路径"**——检索用未合并向量，执行时才合并 | §3：合并造成 ~1/3 排序损失，与 RoPE 无关 | 中 |
| 2 | **检索侧改为"子块多质心"而非块均值**（每块 k 个子质心 + 位置残差） | §3：损伤来自块均值的子结构丢失 | 中 |
| 3 | **阈值在 L2 归一化的方向空间标定**，并报 (假警, 召回) ROC | §4：幅度主导使现有阈值失效 | 低 |
| 4 | **修正 M0 判据为有区分力的版本**：`recall@64(B) − recall@64(A)` 的**单侧检验**，而非"掉点 ≤ A/3" | §3：当前判据在 A≈B 时空洞通过 | 低 |

我们把脚本一并留下（`benchmarks/real_kv_audit_og.py`），可直接复现以上全部数字。

## 6. 一句话

> 我们跑了自己批评他们缺的那个实验，结果**对我们不利、对他们中性**：
> **de-RoPE 合并并没有保住检索排序**（recall@64 0.6685 vs 朴素 0.6846，差距仅 2%），真正的问题是**块均值合并本身损失约 1/3 排序**。
> 同时确认 **σ≈8.03 是 massive-activation 的幅度伪影**（归一化后仅 0.80）。
> 这意味着 LADDER 的改进方向不该是"更小心地处理 RoPE"，而应该是"改变合并的粒度与位置"——**这是我们能给的最有价值的一条建设性结论。**
